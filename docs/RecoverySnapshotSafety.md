# Raw IndexedDB evidence capture

`RecoverySnapshot` has no network, WebView, IndexedDB, activation, repair or parsing API. Its caller must obtain an addressed, valid signed rescue authorization and explicit local consent before invoking it, and must invoke it before the first WebView is initialized in the process. A file being copied successfully does not establish that accounting records can be recovered.

The caller supplies `Context.getDataDir()` and native allowlisted IndexedDB roots. Only `app_webview/Default/IndexedDB`, `app_webview/IndexedDB`, and the equivalent `app_webview_<suffix>` paths below that private data directory are accepted. All files below those IndexedDB roots are treated as opaque evidence, including LevelDB logs, tables, manifests and blob subdirectories. Preferences, native no-backup activation data, Android Keystore and other apps are outside the allowlist.

The destination must be a new `no_backup/data-rescue/<case UUID>/snapshot-<UUID>` directory. A same-named snapshot is never overwritten. The caller must immediately package and encrypt this transient private copy and clean it up before offering export or upload actions. This engine intentionally does not retain plaintext evidence across UI steps. On restart, the integration must remove any incomplete transient snapshot directories using the same pinned cleanup API.

Limits default to 4,096 filesystem entries, a depth of 20 beneath an IndexedDB root, 64 MiB per file, 256 MiB total, and enough free space for twice the source byte count plus 16 MiB. Inventory and aggregate bounds are checked before a destination is created. Missing/empty roots are reported without creating them. All file opens for evidence are read-only and refuse symbolic links; parents below the trusted app-private boundary are checked as well. Special files are excluded.

Copied files are flushed, hashed with SHA-256, checked against source size/modification time/file identity, then compared against a second bounded source hash. A changed or unreadable file produces a failed manifest entry and its partial destination is removed. Errors are stable diagnostic codes without absolute Android paths or file contents. Capture never repairs a file, opens LevelDB, reconstructs a shop, or merges records.

`cleanup` accepts only the exact transient snapshot naming pattern, rejects symbolic links and traverses destination files without following links. It cannot be called with IndexedDB or a generic app directory.

`RecoverySnapshotSelfTest` is executable as a standalone Java main and is wrapped by `RecoverySnapshotTest` for Gradle/JUnit. It uses synthetic binary files only. Its matrix includes byte-identical copies and unchanged source hashes/times, absent/empty roots, activation/outside path denial, destination replay, file/aggregate/count/depth/space bounds, reserve overflow, mutation during capture, interruption, path traversal and cleanup restrictions. Symbolic-link checks are reported as skipped if the host cannot create links. Android startup ordering, process death during packaging, permission UI, physical device behavior and same-signed APK upgrade remain integration/device verification responsibilities.
