## التوافق والأمان

لا يستعمل APK المعتمد Next.js أو Electron؛ هو ملفات approved-runtime وواجهة Android WebView الأصلية. ترقيات تلك المكتبات الخاصة بنسخة الكمبيوتر لا تُنسخ إلى الهاتف ولا تبرر تغيير مشروع Expo القديم غير المستخدم في التوزيع الحالي. تستمر فحوص التوقيع والبوابة الأصلية والمفاتيح العامة واستبعاد أدوات الاختبار من APK الفعلي.

تبقى صيغة الهاتف additive schema4 ما لم يظهر سبب موثق لتغييرها. لا ترحيل يعيد احتساب الأموال أو يعيد ترقيم المستندات القديمة. مراجع المصدر ومعرفاته تبقى محفوظة، لكن فتح قاعدة واحدة والمزامنة بين الجهاز والهاتف لم يُفعّلا. عقد التخزين المشترك وتحويل العمليات الحالية عكسيًا ما زالا مرحلة مستقلة كما هو موضح في دراسة870.

تبقى طلبات الحذف السابقة نافذة: لا تقاص أو أسعار جملة أو أزرار بيانات تجريبية أو طباعة أو نقاط إنشاء مكررة أو أزرار زيادة/إنقاص الكمية. يبقى PDF وXLSX والعربية والفرنسية والليلي والنهاري ومسودات الهاتف والحفظ الذري والتفعيل والنسخ والتحكم عن بعد.

## بوابة التسليم

1. مقارنة القواعد الجديدة مع كود main879 المثبت، بما فيها حالات الرفض والتراجع وفروق الاعتراف بالأجر والافتتاح.
2. فحص JSON وSQLite والتكرار والدمج والأدلة المزورة دون قيد نقدي ثانٍ أو تغيير المعرفات المقبولة.
3. تجربة المسارات فعليًا بواجهة الهاتف، حفظ فاشل وإعادة محاولة وفتح بارد، والعربية/الفرنسية على شاشات صغيرة.
4. الاحتفاظ باختبارات الهاتف السابقة؛ أي توقع تغير بسبب قاعدة جديدة يراجع مع المصدر879 ولا يُحذف لإخفاء فشل.
5. بناء v37 / 1.0.36 بنفس التوقيع وهوية الحزمة، واختبار تثبيته فوق APK27 وAPK36 الأصليين، بالتفعيل المؤقت والدائم وإعادة الفتح والتثبيت المتكرر. لا يُسلّم APK النقل الداخلي قبل اكتمال بوابة verified.

هذه دراسة وخطة تحقق؛ نتيجة التسليم الفعلية تسجل في receipt منفصل بعد نجاح الاختبارات.
